# v0.8.0 Release Notes

v0.8.0 adds the parallel compression engine foundation for CMP2 JSONL streams.

## Highlights

- Added `compact_core::parallel::encode_jsonl_stream_parallel`.
- Added `compact_core::parallel::decode_jsonl_stream_parallel`.
- Added ordered block scheduling so workers may finish out of order while output
  remains deterministic.
- Added `ParallelOptions` and `ParallelDecodeOptions` with checked worker counts.
- Added runtime-agnostic `AsyncJsonlSink` and
  `decode_jsonl_stream_parallel_async_writer` as the stable async writer
  contract.
- Added CLI `compact parallel-bench` to compare sequential and parallel encode
  and decode throughput.

## Compatibility

The parallel encoder writes normal CMP2 streams. Existing CMP2 readers,
inspectors, and bindings can decode the output without a format upgrade.

## Validation

- Parallel encode/decode roundtrip tests.
- Ordering and footer-index preservation tests.
- Worker configuration and worker error propagation tests.
- Corruption rejection for later blocks.
- Repeated multi-worker stress roundtrips.
- CLI benchmark smoke coverage.
- Release benchmark on a generated 5,000,000-row JSONL file.

## Benchmark Results

Run instructions and the reporting template are documented in
[v0.8-benchmark-guide.md](v0.8-benchmark-guide.md).

Release benchmark command:

```sh
target/release/compact parallel-bench /tmp/compact-v08-bench/input-5m.jsonl \
  --schema /tmp/compact-v08-bench/schema.yml \
  --workers 16 \
  --block-rows 10000
```

Environment signal: 16 logical CPUs reported by `nproc`.

| Metric                      |                       Value |
| --------------------------- | --------------------------: |
| Input rows                  |                   5,000,000 |
| Input bytes                 |                 260,500,000 |
| Blocks                      |                         500 |
| Encoded bytes               |                 121,594,522 |
| Compression ratio           |                      0.4668 |
| Sequential encode           |  7,194.362 ms, 34.532 MiB/s |
| Parallel encode, 16 workers | 1,144.080 ms, 217.146 MiB/s |
| Encode speedup              |                      6.288x |

| Parallel decode, 16 workers | 1,273.434 ms, 195.088 MiB/s |
| Decode speedup              |                      2.956x |

## Remaining Hardening

The API and format behavior are stable for v0.8.0. Future hardening should run
the same benchmark matrix on dedicated release hardware to reduce timing noise.
