# v0.5 Search Engine Compression Integration

v0.5 adds search-index compression primitives for inverted-index workloads.
The release focuses on reusable compressed posting lists, sorted term
dictionaries, skip-based docID seek, and small query helpers that prove the
layout can serve search-style access patterns.

## What Is Included

- `compact_core::search::postings`
  - Checked `PST1` posting-list payloads.
  - Delta-varint docID encoding.
  - Delta-varint position encoding.
  - Per-document frequency stream.
  - Serialized skip table.
  - Metadata inspect and seek-by-docID.
- `compact_core::search::dictionary`
  - Checked `TRM1` term dictionary blocks.
  - Lexicographically sorted terms.
  - Binary term lookup.
  - Reusable nested posting-list payloads.
  - Per-term posting inspect and term/docID seek.
- `compact_core::search::query`
  - Single-term docID listing.
  - AND intersection.
  - Adjacent two-term phrase check.
  - Top-k ranking by summed term frequency.
  - Term/docID containment through skip seek.
- CLI search commands:
  - `compact search-encode`
  - `compact search-inspect`
  - `compact search-lookup`
  - `compact search-seek`
  - `compact search-bench`
- Fuzz coverage for search decode paths through `search_decode`.

## CLI Fixture Format

The search CLI uses a deterministic line-based fixture format:

```text
term doc_id positions
```

Example:

```text
brown 1 1
brown 3 4,8
fox 1 2,9
fox 2 1
```

Use `-` for a document with no stored positions:

```text
anchor 42 -
```

## Benchmark Signal

`compact search-bench postings.txt --skip-step 16 --top-k 5` reports:

- term count
- posting payload bytes
- input bytes
- encoded bytes
- compression ratio
- encode time
- metadata inspect time
- top-k term-frequency scan time

These are deterministic CLI-level signals. Lower-noise Criterion benchmarks can
be added later if v0.5 needs performance hardening.

## Limitations

- No tokenizer is included.
- No full search engine or persistent multi-field index is included.
- Query helpers are intentionally small and do not implement BM25 or a planner.
- Phrase support is limited to adjacent two-term checks.
- Entropy coding is still future work.
