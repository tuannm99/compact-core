# v0.9.0 Release Notes

v0.9.0 hardens CMP1-CMP4 for compatibility checks, corruption detection,
recovery, and external schema metadata evolution. It does not introduce a new
wire format.

## Highlights

- Added `compact_core::storage` format detection, version negotiation, and
  schema-independent validation.
- Added complete CMP4 footer, index, row-group header, range, and checksum
  validation.
- Added external stable-ID schema revisions with checked rename, add, remove,
  nullability, default, codec, and type transitions.
- Added evolved decode for legacy CMP2, CMP3, and CMP4 files.
- Added source-bound, copy-on-write CMP2 and CMP4 repair plans.
- Added deterministic external metadata migration from name-based v1 to
  stable-ID v2 while preserving unknown YAML fields.
- Added checked-in compatibility fixtures and corruption matrices.

## CLI

```text
compact validate <file>
compact schema-check <writer-schema> <reader-schema>
compact evolve-decode <input> <output> \
  --writer-schema <writer-schema> \
  --reader-schema <reader-schema>
compact repair <input> --dry-run
compact repair <input> --output <repaired-file>
compact metadata-migrate <schema-v1> \
  --column-id <name=id> \
  --output <schema-v2>
compact repair-bench <damaged-file> --iterations 100
```

Repair and metadata migration never overwrite their input path. Plans are bound
to source length and CRC32 so execution rejects source bytes changed after
planning.

## Compatibility

- Existing CMP1-CMP4 wire formats remain unchanged.
- New readers detect and validate all four existing formats.
- Evolved decode requires both writer and reader schema revisions because
  CMP2-CMP4 do not embed stable schema identity.
- Schema renames match by stable ID, never by name guessing.
- Type changes, tightened nullability, required additions without defaults, and
  older reader revisions are rejected.

## Recovery Guarantees

- CMP2 repair preserves only the contiguous prefix of independently checksummed
  blocks and rebuilds `IDX1`.
- CMP4 repair preserves only the contiguous prefix of independently checksummed
  row groups and reconstructs footer column metadata.
- Recovery stops at the first invalid boundary and never searches corrupt bytes
  for a later magic marker.
- CMP1 and CMP3 cannot be partially repaired because each file is one
  checksummed storage unit.
- CRC32 detects accidental corruption; it is not cryptographic authentication.

## Validation

- Core unit and corruption tests across CMP1-CMP4.
- CLI integration tests for validation, schema evolution, repair, migration,
  and repair benchmarking.
- Checked-in compatible and incompatible schema fixtures.
- Metadata migration preservation and byte-idempotence tests.
- Strict workspace clippy with warnings denied.

## Repair Benchmark

Release-mode benchmark recorded on 2026-06-27 with a generated 100,000-row CMP4
file containing 100 row groups. One footer byte was removed before 100 repair
iterations.

| Metric | Value |
| --- | ---: |
| Damaged input bytes | 460,956 |
| Repaired output bytes | 460,957 |
| Recovered row groups | 100 |
| Recovered rows | 100,000 |
| Plan time | 0.253 ms |
| Total execute time, 100 iterations | 37.337 ms |
| Aggregate execute throughput | 1,177.398 MiB/s |

These are local regression signals, not cross-machine performance guarantees.
The reproduction protocol is documented in
[release hardening](project-knowledge/compact-core/v0.9/06-release-hardening.md).
