# v0.6 Real-Time Streaming Integration

v0.6 adds append-oriented streaming and checkpoint persistence on top of the
existing CMP2 block stream. The release focuses on crash-safe recovery to the
last valid block, replay, rolling segments, and checkpoint snapshots.

## What Is Included

- `compact_core::streaming::append`
  - Append-oriented JSONL streams.
  - CMP2 header and CMP1/BLK1 block reuse.
  - No closing `IDX1` footer for append logs.
  - Recovery to the last fully valid block.
  - Replay from recovered valid prefix.
  - Append after corrupt or truncated tail.
- `compact_core::streaming::snapshot`
  - Checked checkpoint snapshot payloads.
  - Opaque state bytes compressed with the existing byte codec path.
  - Checkpoint ID persisted with the snapshot.
- `compact_core::streaming::rolling`
  - Block-boundary segment rolling.
  - Segment limits by encoded bytes or block count.
- CLI commands:
  - `compact stream-append`
  - `compact stream-recover`
  - `compact stream-replay`
  - `compact stream-roll`
  - `compact stream-bench`
  - `compact snapshot-encode`
  - `compact snapshot-decode`
- Kafka-style integration documentation:
  - `docs/examples/v0.6-kafka-style.md`
- Fuzz coverage:
  - `streaming_decode`

## Recovery Behavior

Append streams are conservative. Recovery scans from the start and stops at the
first partial frame, checksum failure, invalid block payload, non-sequential
block index, or non-sequential row index. Bytes after `valid_len` must be
ignored or truncated before appending new data.

This gives the main safety property:

```text
a failed final write cannot corrupt earlier committed blocks
```

## Benchmark Signal

`compact stream-bench input.jsonl --schema schema.yml --block-rows 10000`
reports:

- block count
- row count
- input bytes
- encoded bytes
- compression ratio
- append time
- recovery time
- replay time
- append throughput
- replay throughput

## Limitations

- No direct Kafka client dependency is included.
- No async runtime dependency is included.
- Exactly-once semantics remain the responsibility of the caller.
- Rolling currently returns segment payloads or writes CLI segment files; it
  does not manage retention policy.
