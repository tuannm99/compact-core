# v0.8 Benchmark Guide

This guide explains how to run, test, and report v0.8 parallel compression
results. Use it when validating a release or comparing scheduler changes.

## 1. Build The Release Binary

Always benchmark the optimized binary. Debug numbers are not release-quality.

```sh
cargo build --release -p compact-cli
```

Expected binary:

```sh
target/release/compact
```

## 2. Create The Benchmark Fixture

Use `/tmp` so generated data does not dirty the repository.

```sh
mkdir -p /tmp/compact-v08-bench

perl -e 'use strict; use warnings;
my $dir="/tmp/compact-v08-bench";
open my $fh, ">", "$dir/input-5m.jsonl" or die $!;
my @levels=("INFO","WARN","ERROR","DEBUG");
my @services=("api","worker","ingest","search","billing");
for my $i (0..4_999_999) {
  printf $fh "{\"ts\":%d,\"level\":\"%s\",\"service\":\"%s\"}\n",
    1_700_000_000 + $i,
    $levels[$i % @levels],
    $services[$i % @services];
}
close $fh;
open my $schema, ">", "$dir/schema.yml" or die $!;
print $schema "columns:\n";
print $schema "  - name: ts\n    type: u64\n    codec: delta_varint_u64\n";
print $schema "  - name: level\n    type: string\n    codec: rle\n";
print $schema "  - name: service\n    type: string\n    codec: rle\n";
close $schema;'
```

Expected fixture:

- `/tmp/compact-v08-bench/input-5m.jsonl`
- `/tmp/compact-v08-bench/schema.yml`
- 5,000,000 JSONL rows
- About 260 MB input

## 3. Run Correctness Tests

Run the full test suite before trusting benchmark numbers:

```sh
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo test --manifest-path fuzz/Cargo.toml
scripts/cross_language_smoke.sh
git diff --check
```

Required result: all commands must pass.

## 4. Run The Benchmark

Record the CPU count first:

```sh
nproc
```

Run the main release benchmark:

```sh
target/release/compact parallel-bench \
  /tmp/compact-v08-bench/input-5m.jsonl \
  --schema /tmp/compact-v08-bench/schema.yml \
  --workers 16 \
  --block-rows 10000
```

For scaling checks, also run:

```sh
for workers in 1 2 4 8 16; do
  target/release/compact parallel-bench \
    /tmp/compact-v08-bench/input-5m.jsonl \
    --schema /tmp/compact-v08-bench/schema.yml \
    --workers "$workers" \
    --block-rows 10000
done
```

The command validates roundtrip internally. If it exits successfully, parallel
output decoded back to the original JSONL.

## 5. Metrics To Report

Copy these fields from `parallel-bench` output:

- `workers`
- `blocks`
- `rows`
- `input_bytes`
- `parallel_encoded_bytes`
- `compression_ratio`
- `sequential_encode_ms`
- `parallel_encode_ms`
- `sequential_encode_mib_s`
- `parallel_encode_mib_s`
- `sequential_decode_ms`
- `parallel_decode_ms`
- `sequential_decode_mib_s`
- `parallel_decode_mib_s`
- `encode_speedup`
- `decode_speedup`

Also report:

- CPU count from `nproc`
- binary type, which must be `target/release/compact`
- fixture row count
- block rows

## 6. Report Format

Use this table in release notes or benchmark reports:

```md
Environment signal: <N> logical CPUs reported by `nproc`.

| Metric                             |                                                      Value |
| ---------------------------------- | ---------------------------------------------------------: |
| Input rows                         |                                                     <rows> |
| Input bytes                        |                                              <input_bytes> |
| Blocks                             |                                                   <blocks> |
| Encoded bytes                      |                                   <parallel_encoded_bytes> |
| Compression ratio                  |                                        <compression_ratio> |
| Sequential encode                  | <sequential_encode_ms> ms, <sequential_encode_mib_s> MiB/s |
| Parallel encode, <workers> workers |     <parallel_encode_ms> ms, <parallel_encode_mib_s> MiB/s |
| Encode speedup                     |                                          <encode_speedup>x |
| Sequential decode                  | <sequential_decode_ms> ms, <sequential_decode_mib_s> MiB/s |
| Parallel decode, <workers> workers |     <parallel_decode_ms> ms, <parallel_decode_mib_s> MiB/s |
| Decode speedup                     |                                          <decode_speedup>x |
```

## 7. Pass Criteria

v0.8 benchmark reporting passes when:

- All correctness commands in section 3 pass.
- `parallel-bench` exits successfully.
- `parallel_encoded_bytes` equals `sequential_encoded_bytes`.
- `encode_speedup` is greater than `1.0`.
- `decode_speedup` is greater than `1.0`.
- The final report includes environment, fixture, throughput, and speedup data.

## 8. Cleanup

Generated benchmark data is disposable:

```sh
rm -rf /tmp/compact-v08-bench
```
